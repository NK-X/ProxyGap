# 平地低速／近原地转向可行性诊断

> 日期：2026-08-19<br>
> 状态：现有 V22 checkpoint 的只读、分布外诊断；没有训练<br>
> 配置：`configs/flat_low_speed_turn_diagnostic_v1_20260819.json`<br>
> 脚本：`scripts/evaluate_flat_low_speed_turn.py`

## 1. 结论

当前 V22 策略尚不能可靠完成受限漂移的 90°或 180°近原地转向。12 个平地 episode 中只有
`1/12` 曾在 10°容差内维持 0.5 s，但该轮最大质心漂移 `2.387 m`，超过预声明的 `1.0 m`；
受限漂移成功和全程无四足腾空的安全合格成功均为 `0/12`。没有 episode 摔倒，但所有条件均出现
四足端同时无接触。因此，现有 checkpoint 不应直接作为凹坑脱困的“原地转向技能”。

这并不证明四腿 8 自由度机械结构无法原地转向。本轮测试仍是小正速度、高曲率的分布外近似；
当前软件接口在速度为零时会先报错，真正零速偏航尚未被测试。

## 2. 当前接口为什么不支持真正原地转向

`CurvedGaitCommandWrapper.set_external_curve_command` 使用：

```text
target_speed = positive(speed)
curvature = yaw_rate / target_speed
abs(curvature) <= max_abs_curvature
```

所以 `speed=0, yaw_rate!=0` 会在计算曲率前被拒绝。固定目标控制器还把最大偏航速度设成
`speed*maximum_abs_curvature`；速度越低，允许偏航越小。这是“前进曲线”的接口，而不是独立的
线速度—角速度接口。不能把该软件限制误写成机械结构限制。

本轮没有修改核心代码，而是在独立评价环境中把曲率诊断上限临时放宽到 `6.0 m^-1`，使
`0.05 m/s` 时能传入 `0.30 rad/s` 的偏航命令。该值远超 V22 的训练速度 `0.8 m/s` 和最大曲率
`0.25 m^-1`，只用于判断现有策略是否已有可复用能力，不能保留为正式控制参数。

训练 run；结果只能否定“当前策略已经可靠具备该技能”，不能估计总体成功概率。

## 4. 最小独立训练协议

如果要单独训练该技能，建议新建 checkpoint 和 wrapper 变体，不覆盖 V22：

1. 将外部接口改为分别限制 `linear_speed>=0` 与 `abs(yaw_rate)<=max_yaw_rate`；
2. `linear_speed=0` 时不计算 `yaw_rate/speed`，曲率记为“不适用”，直接使用角速度命令；
3. 观察维度可暂时保持不变：现有 command 已包含前进速度、偏航速度和航向误差；
4. 课程按 `0.10 m/s -> 0.05 m/s -> 0.00 m/s`，角度按双向 45°、90°、180°递增；
5. 奖励只针对转角／角速度跟踪、质心位移与平面速度、支撑、腾空、倾倒和动作变化；
6. 本阶段不加入能耗奖励，以免把“不转”错误优化成低能耗；只记录关节运动和持力，技能通过后再
   用 V2 单独标定原地转向能耗；
7. 预先冻结漂移、完成时间、无摔倒和腾空门槛，并使用多个独立训练 seed 与未用于调参的评价 seed。

建议第一道保留门槛是：90°和 180°、左右两个方向均能在固定时限内完成，最大质心漂移不超过
预声明阈值，无摔倒，四足腾空显著低于当前策略；若需要“严格不跳跃”，正式合格仍要求零腾空。
当前诊断不支持直接启动长训练，但支持建立这个独立短 pilot。

## 5. 它能否高置信度解决凹坑停滞

不能。必须区分：

- **能转向**：低层能在有限足迹内改变身体朝向；
- **有可通行路线**：转向后的方向存在坡度、净空、摩擦和曲率均可执行的出口；
- **能爬出**：低层在该出口坡面能持续支撑并产生推进。

原地转向技能可以减少为了换方向而走大圆弧的空间需求，也可能帮助高层执行重规划路线；但如果
凹坑没有满足已验证最大坡度的出口、出口太窄、机器人不能后退且转向足迹不足，或低层仍无法在
坡面形成支撑，转向只会让机器人在坑内换朝向。高层仍需用已观测 cost map 判断是否存在路线；
无路线时应返回 `no_valid_route` 并安全停止，而不是反复旋转。

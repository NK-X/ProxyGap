# V3 系统最终多目标完整地图评测报告

日期：2026-08-20（Europe/London）
状态：正式结果已完成；三种评价体系的视频已逐帧验证
研究边界：同一张已知冻结地图、三个预声明评测种子；不是未见地图泛化或全局最优证明

## 1. 最终结论

最终系统在冻结的 80 m × 80 m 连续起伏地图上完成了 6/6 次正式任务：两条候选路线合同分别使用三个预声明新种子评测，所有回合都进入终点 1.5 m 圈，并在 2.0 m 圈内保持 2 s；无摔倒、无躯干触地、无持续非足接触、无持续的 force-qualified corrected-slip event。

三个用户偏好采用同一候选集内的归一化加权目标：

\[
J = w_T(T/T_{\min}) + w_E(W^+/W^+_{\min}),
\]

其中 \(T\) 为完成时间，\(W^+\) 为执行器正机械功代理。该代理不等同于电池能耗。15 个可行候选中，时间优先（0.8/0.2）和平衡（0.5/0.5）选中同一合同；能耗优先（0.2/0.8）选中另一合同。因此系统提供三种评价语义，但只有两条唯一路线合同。

## 2. 为什么此前视频不能到达，而本轮可以

此前 post-seal direct-goal 测试使用最终 PAIR0 checkpoint 直接朝终点给低层控制命令。该策略在 600 s 内只取得 14.51 m 最佳推进，并没有全局选路能力。单纯延长训练或加入左右转向曝光也没有通过预声明转向门。

本轮没有把失败隐藏起来，而是分解问题：

1. 对封存 checkpoint 做只读转向筛查，发现旧 V4 canonical-frame checkpoint 是唯一能在平地同时响应左右命令的候选；
2. 在 PAIR0 接触合同下复核其平地、±8°和+12°标准坡面安全性；
3. 拒绝会在15 s内摔倒的 V4/PAIR0 action blending；
4. 使用已知冻结地图的高层 route planner 生成满足16°离散坡度代理约束的 waypoint route；
5. 保留 V4 作为低层局部命令跟随器，PAIR0 作为接触合同；
6. 对路线成本与坡度速度计划形成15个可行候选，再按三种权重预先选择；
7. 最后用三个未参与候选选择的哈希派生评测种子做 6 回合正式验证。

因此改进是系统级集成：`known-map route selection + waypoint follower + V4 low-level controller + PAIR0 contact contract`。它不是一次新的 PPO 训练，也不是证明最终 PAIR0 policy 已学会全局地图。

## 4. “不滑倒或少滑倒”的精确定义

所有正式回合均满足：

- fall = 0；
- torso-ground = 0；
- sustained non-foot ground contact = 0；
- duration-corrected sustained slip event = 0；
- 所有状态与能耗记录有限。

但是“持续滑移事件为0”不等于“脚在每个瞬间都不滑”。正式回合仍出现短暂 force-qualified slip candidate samples，并且约9–10%的完整0.05 s控制区间在五个物理子步中四足均无接触；约三分之一的0.01 s物理子步为 zero-foot。系统完成了任务且没有摔倒，但步态仍有明显腾空，不应称为生物学自然步态或持续静态稳定。

## 6. 研究解释与局限

可支持的结论：

- 在同一张已知冻结地图上，两条候选路线合同对三个新 reset seed 均完成任务；
- 高层已知地图选路解决了 direct-goal controller 无法绕行的问题；
- V4 低层 checkpoint 在该系统中比最终 PAIR0 checkpoint 更适合双向 waypoint 跟随；
- 三种人类偏好可以通过先满足成功/安全硬门，再在候选完成轨迹中比较时间与机械功代理来实现。

不能支持的结论：

- 未见地图泛化；
- V4 checkpoint 单独解决完整地图；
- 路线或完成时间为数学全局最优；
- 机械功代理等于电池能量；
- 零瞬时滑动或自然步态；
- 多独立训练 seed 的学习稳健性。

最终项目应把 direct-goal 失败与 waypoint-system 成功并列展示。前者证明局部低层控制不足以自行完成全局导航，后者证明在明确分层后，同一物理系统能够以可审计路线完成任务。

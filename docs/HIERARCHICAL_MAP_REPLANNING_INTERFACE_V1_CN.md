# 全局地图—局部运动分层规划接口 V1

> 日期：2026-08-19<br>
> 状态：独立离线规划 smoke；没有训练或修改低层策略<br>
> 配置：`configs/fixed_map_hierarchical_replanner_smoke_v1_20260819.json`<br>
> 脚本：`scripts/smoke_fixed_map_hierarchical_replanner.py`

## 1. 决策结论

不建议把完整高度网格直接拼接到当前低层 PPO observation；本轮封存输入实际为
`1025×1025=1,050,625` 个高度值。完整地图应由
**高层规划器**使用，低层策略只接收身体附近的相对高度、地形法向、有符号坡度、足端接触历史，
以及高层生成的前进速度、目标航向和偏航命令。

原因不是“神经网络绝对处理不了完整网格”，而是职责与证据不匹配：

- 低层每个控制步解决落脚、支撑和姿态，完整地图的大部分像素与当前动作无关；
- 直接展平会把低层输入从 135 维扩大到约 26 万维，显著增加参数、样本和迁移成本；
- 固定尺寸和绝对坐标容易记忆当前封存地图，不能自然适配不同面积、分辨率或旋转后的地图；
- 全局“走哪条路”和局部“怎样稳定走”混入同一策略后，低到达时无法区分规划失败与步态失败；
- 当前 13 维局部预瞄尚未被策略有效利用，先加入更大的全图输入缺乏实验依据。

若未来希望高层也由神经网络学习，可让高层以较低频率使用 cost map 的 CNN/图网络编码；这仍不等于
把完整 heightfield 直接交给 20 Hz 低层关节策略。

## 2. 推荐架构边界

```text
已知全局地图，或未知地图中已观测的区域
                  ↓
高层 cost map
  坡度硬约束 + 距离 + 升降 + 转向/曲率代理 + 失败记忆
                  ↓
A* / Hybrid A* / D* Lite
                  ↓
局部 waypoint + target heading + forward-speed schedule
                  ↓
低层 8-DOF policy
  局部相对高度 + 法向 + 坡度 + 足端接触 + command
                  ↓
MuJoCo 状态、校正后滑移、推进/停滞、支撑与摔倒
                  └───────────反馈高层失败记忆与重规划
```

职责固定为：

| 模块 | 可以决定 | 不应决定 |
|---|---|---|
| 高层规划 | 路线、航点、速度计划、不可通行区、重规划 | 8 个关节动作、具体落脚 |
| 低层策略 | 如何实现前进/偏航并适应局部地形 | 全局路线、人的时间—能耗权重 |
| 安全/状态机 | 确认持续滑移、停滞、摔倒并暂停/终止 | 伪造一条低代价路线 |
| 能耗模块 | 记录实际执行能耗代理 | 把失败或少推进判为节能 |

## 3. A*、Hybrid A* 与 D* Lite 的选择

### 3.1 当前原型：heading-state A*

封存地图完整已知，图规模在 `0.5 m` 网格上可控，且当前首要问题是验证代价和接口，因此第一版
使用 heading-state A*。状态包含网格位置与进入方向，边代价可审计为：

```math
C_e=C_L+C_S+C_U+C_D+C_R+C_K+C_F.
```

- `CL`：路径长度；
- `CS`：坡度比例平方成本，超过 16°的足端走廊直接不可通行；
- `CU/CD`：累计上升/下降成本，V1 设上升权重大于下降；
- `CR`：航向改变；
- `CK`：`|Delta psi|/Delta s` 的离散曲率代理；
- `CF`：已确认失败区域的软 halo 成本，中心硬半径不可通行。

这些是无量纲规划成本，不是 V2 能耗，也没有进入 PPO 奖励。离散曲率只用于偏好更平滑路线，
不能证明 MuJoCo 执行时满足动态曲率上限。真正的路径执行仍需低层动力学回放。

### 3.2 何时使用 Hybrid A*

当“只前进、不后退”、最小转弯半径和连续航向成为正式高层硬约束时，使用 Hybrid A* 更合适。
不过当前命令接口仍不能表达零速非零偏航，且底层尚未通过支撑门槛；在这些问题解决前，直接把
Hybrid A* 的运动学可行性当成动力学可行性会夸大证据。

### 3.3 何时升级 D* Lite

如果地图未知、局部观测持续更新，或同一 episode 内多次把滑移/停滞区域加入 cost map，反复从头
运行 A* 会重复计算。此时 D* Lite 可以复用上一次搜索结果，作为在线重规划升级。当前 smoke 只
注入一个失败区域，A* 足以验证接口；不能仅因 D* Lite 更先进就增加第一版实现复杂度。

## 4. 持续滑移与停滞如何触发重规划

不能用单步足端切向速度超限直接封路，因为既有审计表明它主要混合落脚瞬态。高层只接收已经过
下列门控的事件：

### 4.1 持续滑移事件

- 落脚后 `0.10 s` 宽限；
- 足端法向力至少 `1 N`；
- 足端切向接触速度连续至少 `0.20 s` 超过 `0.20 m/s`；
- 记录脚编号、位置、持续时间和滑移方向。

### 4.2 停滞事件

当高层持续发出至少 `0.10 m/s` 前进命令，但在 `1.0 s` 窗口内对活动 waypoint 的推进不足
`0.05 m`，记为停滞候选。应同时记录支撑、航向误差和身体速度，用于区分：

- 支撑失效；
- 路线不可通行；
- 偏航命令饱和；
- 已到 waypoint 但切换逻辑错误。

阈值目前是 smoke 参数，必须在标准坡台与验证地图标定后才能冻结。

### 4.3 状态机连接

```text
FOLLOW_ROUTE
  → CONFIRM_SLIP_OR_STALL
  → RAMP_TO_SAFE_SPEED
  → ADD_LOCAL_FAILURE_REGION
  → REPLAN
  → RESUME_WITH_NEW_WAYPOINTS
      或 SAFE_STOP / no_valid_route
```

一次确认事件在当前位置建立 `1.5 m` 硬阻塞区和延伸至 `3.0 m` 的软代价 halo，避免新路线紧贴
故障边缘。重规划需要冷却时间，避免在同一区域每个控制步重复触发。连续两次重规划仍失败后进入
安全停止，而不是无限摆动或继续冲坡。

当前接口要求前进速度严格为正，不能执行真正零速原地偏航。因此 V1 的 `RAMP_TO_SAFE_SPEED` 只能
降至可控的很小正速度或安全 hold；待独立原地转向接口实现后，才可在恢复路线前执行“质心近似不动
的定向”。规划器不能假设当前低层已经拥有该能力。

## 5. 已知地图与未知地图必须分成两个协议

### 5.1 已知地图任务

允许高层在 episode 开始时读取完整地图；低层仍不读取全图。这测试的是跨地图的规划与执行，而
不是在线建图。正式泛化时，地图 seed 必须按训练/验证/测试隔离；封存地图已经反复调试，只能保留
为开发地图。

### 5.2 未知地图任务

高层只维护 `known_mask` 和已观测局部 height/cost；未观测区域不能查询隐藏的 test heightfield。
可以采用：

1. 未知区域设非零探索成本，而不是默认免费；
2. 规划到可见 frontier 或当前可证安全的局部 waypoint；
3. 新局部高度/坡度到达后更新 cost map；
4. 由 D* Lite 增量重规划；
5. 无可证安全路线时停止并报告 `no_valid_route`。

已知地图和未知地图的结果不能合并成一个成功率，因为前者具有完整先验信息，后者还包含感知与探索
误差。任何用于调试或阈值调整的地图都不能继续作为未见 test map。

## 6. 本轮独立 smoke 的验收口径

脚本在封存高度数组上：

1. 生成包含坡度、升降、转向和曲率代理的起终点路线；
2. 在原路线中段模拟一个经过持续滑移门控的失败位置；
3. 从失败之前的当前位置重新规划；
4. 验证新路线不进入硬失败半径且与原剩余路线不同；
5. 保存两条路线、失败区域、逐项成本、配置、脚本副本和 SHA-256；
6. 明确记录没有加载 checkpoint、没有训练、没有修改地图/摩擦/能耗。

正式产物入口：`artifacts/dev/fixed_map_hierarchical_replanner_smoke_v1_corrected_20260819/`。

该 smoke 只能支持“高层 cost map 与故障重规划机制可运行”。它不支持“机器人能执行新路线”、
“路线是 V2 能耗最优”或“对未知地图泛化”。下一道门槛是使用同一冻结低层策略对 baseline 与
replanned waypoints 做配对动力学回放；在低层悬空问题修复前，该回放仍应视为诊断而非成功证明。
